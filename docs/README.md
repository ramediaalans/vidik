## Генерируемые отчёты

- [video-inventory.md](video-inventory.md): срез записей из films.ts и airtime.json. Генератор перечисляет основной source карточки фильма/сериала, а **не каждый элемент episodes-плейлиста**. Это не исчерпывающий список всех видео и не проверка доступности внешних ссылок. Длительность берётся из source.duration: для сборника это может быть длительность всего исходного ролика, а не отдельного фильма/серии с учётом start/endTrim.
- [tv-grid-3-days.md](tv-grid-3-days.md): развёрнутые слоты A/B/C из airtime.json. **Внимание:** сайт теперь вещает по `app/src/tv/grid.json`, а генератор по-прежнему читает airtime.json, поэтому этот отчёт не совпадает с текущим эфиром. Актуальная программа — `program.ts` / телегазета на /televizor. Чтобы отчёт снова был верным, генератор нужно перевести на grid.json. Технические слоты входят в число «передач», реклама показана отдельно. В интерфейсной газетной программе межпрограммка скрыта.

Перегенерация из корня, без сетевых запросов и без изменения каталогов приложения:

```powershell
node tools/report/inventory.mjs
```

Порядок работы: изменить согласованные входные данные → проверить приложение → обновить отчёты → проверить diff. Не править таблицы вручную как источник данных для приложения.

## Исторические документы

- [tv-setka-3-dnya.md](tv-setka-3-dnya.md): исходное редакционное ТЗ; приоритеты балансеров, количество нужных источников и плановые названия не описывают текущий runtime.
- [tv-content-final.md](tv-content-final.md): исторический отчёт этапа подбора/проверки. Старые ✔ не доказывают доступность сейчас. Его генератор tools/tv/collect/report.mjs опирается на старые проверки Vibix и не умеет корректно ссылаться на VK; не применять его для обновления актуального инвентаря.

Не запускать поиск/подбор источников, старые SDK-проверки или генераторы airtime автоматически ради обновления документации. Они могут делать сетевые запросы, менять большой объём данных и требовать секреты.
