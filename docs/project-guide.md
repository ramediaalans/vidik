# ВИДИК — архитектура, контент и проверки

Это руководство по текущей реализации. Инфраструктура — [DEPLOY.md](../DEPLOY.md), визуальные принципы — [DESIGN.md](../DESIGN.md). Все команды tools запускать из корня проекта. Перед изменениями проверить git status; commit/push/deploy и публичные загрузки — только после явного разрешения пользователя.

## 1. Три разных телевизора

| Раздел | Компонент / ресурс | Что менять |
| --- | --- | --- |
| `/televizor` | `app/src/tv/TVPlayer.tsx`, `images/tv/tv-frame.webp`, `tv-knob.webp` | эфир, ручка каналов, шторки, стили `.tv__*` |
| Видеосалон / Дисней-клуб | `TvSet.tsx`, `images/tv/tv-vcr-frame.webp` | `.tvset*`, экран, кассета, часы VcrClock |
| `/igry/:id` | `Emulator.tsx`, `tv-plain.webp`, `console-{nes,md,snes}.webp` | `.emu__*`, `consoles.ts`, вставленный картридж |

Не менять общий телевизор другого раздела при задаче только на игровую страницу. Игровой декор скрывается в fullscreen. Старый `game-tv.webp` может оставаться локально после генерации, но не является активной объединённой рамкой игры и удалён из Git. `build-carts.py` ещё может создавать его как побочный результат — не коммитить его автоматически.

Генерация игровой рамки и приставок:

```powershell
python tools/games/build-consoles.py "<папка с исходными картинками>"
```

По умолчанию — Downloads; имена файлов, SLOT и параметры экрана задаются в скрипте. Выходы: `app/public/images/tv/` и `app/src/data/consoles.ts`. Проверить альфа-канал экрана, слот картриджа и масштаб всех трёх приставок.

## 2. Игры и сохранения

- `roms.ts`: тип Rom, базовые записи и объединение с `roms-more.ts`.
- `rom-art.ts`: отдельные арты; `rom-carts.ts`: изображения готовых картриджей; `consoles.ts`: геометрия телевизора/приставок.
- `CartridgeShelf.tsx`: поиск/фильтрация, сортировка NES → Sega → SNES, внутри по title.
- `Emulator.tsx`: Nostalgist, фиксированный буфер canvas и CSS-масштабирование. Не менять разрешение буфера при fullscreen без проверки: ядро может не пересчитать GL viewport.
- `media/framePacer.ts`: ограничение частоты для быстрых мониторов; не удалять как «лишний» rAF-код.
- `SaveShelf`, `media/saves.ts`: слоты сохранений; `GamepadSetup`, `media/gamepad.ts`: геймпады; `TouchPad`: экранное управление. Не менять формат сохранений без миграции.

### Добавить игру

1. Выбрать стабильный уникальный id, проверить отсутствие дубля. Метаданные: title/nick/year/platform/genre/players/memory.
2. Привязать file `roms/<имя>.<ext>` и core: NES → fceumm; Mega Drive → genesis_plus_gx; SNES → snes9x. Точные platform: `Dendy / NES`, `Sega Mega Drive`, `Super Nintendo`.
3. Для дополнительного NES/MD-набора править исходный список `tools/games/new-games.py`, затем согласованно запускать:

```powershell
python tools/games/add-games.py "<папка ROMs/1>"
```

Скрипт ожидает подпапки Gen/NES, распаковывает ROM и генерирует roms-more.ts. Для 7z нужен py7zr. Это массовый импорт, не универсальный инструмент для SNES. Старый tools/import-roms.mjs содержит абсолютные SRC/DST и перезаписывает индекс — не запускать вслепую.

4. Добавить наклейку в `tools/games/labels/` и запись в `new-labels.json` по существующей схеме; базовые наклейки также заданы в LABELS внутри build-carts.py. Сборка:

```powershell
python tools/games/build-carts.py "<папка исходных корпусов/наклеек>"
```

Проверить выходные картриджи и `rom-carts.ts`; генератор может скачать внешние обложки, пересобрать весь набор и создать legacy game-tv.webp.

5. ROM исключён из Git; после разрешения загрузить в R2 (см. DEPLOY.md). Картинка/карта/метаданные — в Git после отдельного разрешения commit/push.
6. Проверить реальный boot, управление, паузу, звук, fullscreen, сохранения. HTTP 200 не означает, что ROM работает.

## 3. Музыка

```powershell
node tools/import-music.mjs --src "D:\Музыка" --bitrate 128k
```

Нужны ffmpeg и ffprobe в PATH. Генератор читает ID3, перекодирует MP3 и перезаписывает `tracks.ts`. Перед запуском проверить папку, ожидаемый набор и diff плейлиста. MP3 — в public/music локально и отдельно в R2.

Интерфейс раздела — `v2/Boombox.tsx` + `boombox.css` (магнитофон: питание, ролики, бегущая строка, панель клавиш) и плейлист под ним. Сборник на «Ностальгии» — `v2/MixTape.tsx`, берёт реальные треки из `tracks.ts`. Виджет «Кассетник» в углу — компактная плашка того же плеера.

Webamp (`media/player.tsx`) монтируется вне React-дерева и остаётся звуковым движком; PlayerProvider поддерживает непрерывность при навигации. Игры/видео должны использовать существующий claimAudio, а не создавать конкурирующий глобальный звук.

## 4. Фильмы и Дисней-клуб

Текущая цепочка: `FilmPage` → `TvSet` → `ExternalVideoPlayer` → VK/Rutube/YouTube iframe. Балансеры могут участвовать в инструментах получения метаданных, но **не являются активным runtime-плеером**. Компонента VibixPlayer в текущем src нет.

`films.ts` генерируется `tools/films/build-catalog.mjs`. Входы — `tools/films/selection.json` и `source-overrides.json`; ручные записи подбора — `manual-selection.json`. `source` описывает основной проверенный ролик; `episodes` — реальные отдельные видео для плейлиста; метаданные seasons не доказывают наличие всех этих серий в просмотре.

### Источники метаданных (с октября 2026)

`tools/films/resolve.mjs` подбирает карточки для списков `SALON` и `DISNEY` внутри скрипта и пишет `selection.json`:

1. **TMDB** — основной источник (ключ `TMDB_API_KEY` в `.env`): русское название, описание, постер, фон, жанры, страны, длительность, сезоны, режиссёры (`directors`) и актёры (`cast`, до 10).
2. **Архив Vibix** `archive/vibix/cards.json` — запасной: ID и рейтинг Кинопоиска, озвучки, короткое описание, русское описание, если у TMDB его нет; целиком — если фильма нет в TMDB. Связь по IMDb ID, иначе по русскому названию и году. Архив собран `tools/vibix-archive/archive.mjs` (см. его README), лежит вне Git; API Vibix после декабря 2026 недоступен, скрипты к нему больше не обращаются.
3. **Ручные карточки** `manual-selection.json` имеют приоритет: позиция списка с ручной карточкой не подбирается автоматически.

Без флагов `resolve.mjs` не трогает уже подобранные записи `selection.json` (там бывают ручные правки) и дописывает только новые позиции в конец. `--dry` — записать результат в `selection.dry.json` для просмотра; `--refresh` — переподобрать всё (сначала сравнить с `--dry`, потому что меняются описания и постеры уже опубликованных фильмов). `directors`/`cast` пока остаются в `selection.json` и в `films.ts` не попадают.

Добавить фильм: `['Название', год]` в `SALON`/`DISNEY` → `node tools/films/resolve.mjs --dry`, проверить совпадение → `node tools/films/resolve.mjs` → проверенный ролик в `source-overrides.json` (ключ — slug из названия и года) → `node tools/films/build-catalog.mjs`. Без записи в `source-overrides.json` сборка каталога останавливается.

**Сеть и DNS.** Провайдер подменяет DNS-ответы для `api.themoviedb.org` и `image.tmdb.org` (заглушка `::1`/`127.0.0.1`), браузер с защищённым DNS этого не замечает. Скрипты `resolve.mjs`, `build-catalog.mjs` и `vibix-archive/archive.mjs` ходят в сеть через `tools/lib/net.mjs`: имя резолвится через 1.1.1.1/8.8.8.8, затем DNS-over-HTTPS, и только потом системный DNS (адреса-заглушки отбрасываются). Новые скрипты, обращающиеся к TMDB, делать через `netFetch`, а не глобальный `fetch`. TMDB требует указывать себя как источник данных и картинок.

Инструменты, выбирать нужные шаги, а не запускать весь конвейер автоматически:

```powershell
node tools/films/apply-overrides.mjs
node tools/films/resolve.mjs
node tools/films/vk-poster.mjs
node tools/films/build-catalog.mjs
node tools/films/audit-sources.mjs
```

Они могут обращаться к внешним API, менять selection.json/постеры/каталог и требовать секреты. Прочитать код выбранного шага, проверить входы, сохранить чужие изменения. Править films.ts вручную как постоянное решение не следует.

Прогресс просмотра — `media/watchProgress.ts` и localStorage `vidik:watch:v1`; ключ зависит от slug и серии. Часы VCR — отдельные `VcrClock`/`media/vcrClock.ts`. Экранные состояния загрузки, паузы, рекламы/ошибки — в ExternalVideoPlayer, небольшое видео помех — public/video/vhs-noise.mp4. Не обещать полную поддержку API/продолжения у любого нового провайдера: тестировать его отдельно.

## 5. Линейный эфир

- Имена/номера каналов: `app/src/tv/data.ts` (id: pervaya, shestaya, kabelny; данные каналов из `pool.json`).
- Сетка эфира: `app/src/tv/grid.json`, её читает `schedule.ts`. Пересборка — `python tools/tv/xlsx_to_grid.py <vidik-content-audit.xlsx> app/src/tv/grid.json` (нужен openpyxl, лист «ТВ»). Руками grid.json не править.
- Время: UTC+3 независимо от часового пояса браузера. Эпоха `2026-01-01` = A, затем B/C/A.
- Газетная программа: `program.ts` (TV_PROGRAM) → `TvNewspaper.tsx`. Подписи на кнопках каналов (канал / передача) и строка «Далее» берутся из той же программы через `onAir.ts` (`programOnAir`, `clockOf`), чтобы совпадать с газетой.
- `airtime.json` в приложении больше не используется; его читает только отчёт `tools/report/inventory.mjs`, поэтому `tv-grid-3-days.md` отражает старую airtime-сетку, а не grid.json.
- Плашка «Прогревается кинескоп…» висит, пока плеер не сообщил onReady для текущего `airKey`. Не сбрасывать `readyFor` асинхронно (setTimeout) при смене канала: VK с закэшированным API отвечает раньше, и плашка залипает поверх эфира.
- Внутри блоков после программ вставляется межпрограммка, контент циклически заполняет блок до следующего якоря; последний ролик может быть обрезан границей. Поэтому время блока в airtime и каждая строка фактической сетки — не одно и то же.
- TVPlayer присоединяется к текущему моменту эфира, пользовательской перемотки нет. Generated — локальная техническая таблица; VK/Rutube/YouTube — реальные внешние видео.

Конвейер `tools/tv/collect/build-final.mjs` пересобирает airtime/pool-flat.json из подобранных данных — это прежняя цепочка, на текущий эфир (grid.json) она не влияет. Не запускать ради «обновления README»: он меняет контент. Исторический `collect/report.mjs` не поддерживает актуальные VK-ссылки и опирается на старые проверки — для текущих отчётов использовать inventory.mjs.

## 6. Изображения

Обычные фирменные кадры: исходники assets_raw → `node tools/optimize.mjs` → public/images. Этот оптимизатор читает только непосредственные PNG/JPG в assets_raw и использует PLAN/defaultsFor, не рекурсивно импортирует любую папку. Размеры и пути определяет код генератора; не все картинки обязаны быть 1600×800.

Корпуса/вырезанные экраны требуют отдельной обработки с сохранением прозрачности и соответствующей геометрии. Наклейки игр могут содержать встроенные названия/персонажей; это исключение из правил нейтральных фоновых иллюстраций. Реальные постеры/обложки присутствуют — соблюдать права и сохранять происхождение.

Старый `tools/link-art.mjs` работает с assets_raw/games_art и базовыми записями, прочитанными из roms.ts; не охватывает автоматически roms-more.ts. Перезаписывает rom-art.ts. Он не заменяет современную сборку готовых картриджей build-carts.py.

Из-за immutable-кэша публичных изображений замена под тем же именем может не обновиться у пользователя: см. DEPLOY.md.

## 7. Визуал v2 и компьютерный клуб

- Слой v2: `app/src/redesign.css` + `fonts.css` поверх `styles.css`, компоненты — `app/src/v2/`. Меню-«комнаты» с эфирным временем — `v2/rooms.ts` и `components/Layout.tsx`.
- Новые фоны — `public/images/v3/`; подмена старых путей — `V3_MAP` в `media/asset.ts`. Новый фон добавлять туда же с новым именем файла (immutable-кэш).
- Подвал: надпись ВИДИК с текстурой-плакатом и параллаксом — `v2/footParallax.ts`.
- `/retrointernet`: `v2/RetroDesktop.tsx` + `retro.css`; ярлыки «Мой компьютер» ведут на реальные разделы.
- Чат: `v2/IcqChat.tsx` — имитация ICQ с ботами, без сервера; сообщения никуда не отправляются.
- `/pc/` — статика в `public/pc/` (index.html, desk/*, play/, engines/). Шапка сайта на этой странице — `pc/desk/head.css` + `head.js`, повторяет меню `rooms.ts`: при изменении разделов править оба места. В dev `/pc/` отдаёт плагин `pcIndex` в vite.config.ts.
- Пыль/частицы на canvas пробовали и убрали из-за тормозов — не возвращать.

## 8. Проверки и отчёты

Из app: `npm run lint` и `npm run build`. Корневой npm test не является проверкой. Oxlint настроен в `app/.oxlintrc.json`; собранный чужой код `public/pc/**` (порты Diablo и др.) исключён через `ignorePatterns`, поэтому `npm run lint` проверяет только исходники проекта и должен завершаться без ошибок (предупреждения допустимы). Затем свежий preview и браузерный сценарий из корня, например:

```powershell
node tools/probe.mjs --url http://localhost:4173/igry/chip-n-dale#play --steps tools/steps/game-page.js --out qa/game-page.png --w 1440 --h 1000 --dpr 1 --wait 60000
node tools/probe.mjs --url http://localhost:4173/muzyka --steps tools/steps/music.js --out qa/music.png
node tools/probe.mjs --url http://localhost:4173/videosalon/terminator-2-sudnyy-den-1991 --steps tools/steps/film-page.js --out qa/film.png
node tools/report/inventory.mjs
```

Сначала прочитать сценарий и проверить, что селекторы соответствуют текущему UI. QA-файлы не коммитить. Проверять desktop/mobile, ошибки консоли, навигацию и прямые URL; для игры — NES/MD/SNES.

**Ограничение старых тестов:** tools/tv/test-schedule.mjs включает устаревшее ожидание Kodik для аниме-блока. Его падение в этом месте не доказывает неисправность активного VK/Rutube/YouTube-эфира. Отдельно проверить актуальные источники и не менять приложение ради удовлетворения старого assert. Исторические probe-balancers/vibix-* скрипты — исследовательские инструменты, не production acceptance suite.

Отчёты не проверяют доступность видео онлайн. video-inventory перечисляет основной source, не все episodes. Точные рамки/назначение каждого документа — [docs/README.md](README.md).
